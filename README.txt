# Power BI Assignment — Bike Sharing

## Included files
- `Cleaned_Bike_Stations.csv`: cleaned import-ready table, split coordinates, parsed timestamps and data-quality flags.
- `PowerQuery_Transformations.m`: Power Query M code. Update the file path before using.
- `DAX_Measures.txt`: DAX measures and calculated columns.
- `DimStation.csv`, `DimCity.csv`, `DimDate.csv`, `FactStationSnapshot.csv`: suggested modeling tables.
- `One_Page_Executive_Summary.pdf`: concise summary for submission.
- `Stations_by_City.png`, `Station_Status.png`: sample chart images.

## Important limitation
The provided Excel has 2,856 station records, 25 contract labels and fields for capacity, available bikes/docks, status, coordinates and last update. It has **no revenue, distance travelled, trip count or historical revenue data**, so revenue-per-km and revenue-over-time questions in the assignment cannot be calculated honestly from this source alone.

## Recommended Power BI steps
1. Open Power BI Desktop → Get Data → Text/CSV → select `Cleaned_Bike_Stations.csv`.
2. In Power Query, inspect types and applied steps. If using the `.m` script instead, update the Excel path in the Source line.
3. Rename the loaded query `BikeStations` if you want to use the provided DAX as written.
4. Create the measures from `DAX_Measures.txt`.
5. Build one report page with:
   - Cards: Station Count, Open Stations, Closed Stations, Total Bike Capacity, Available Bikes.
   - Bar chart: ContractName by Station Count.
   - Stacked column or donut: Status.
   - Bar chart: Available Bikes by ContractName.
   - Scatter chart: BikeStands vs AvailableBikes.
   - Map: Latitude and Longitude, size by AvailableBikes.
   - Slicers: ContractName, Status, Banking, Bonus.
6. For a true star schema, load the supplied `DimStation`, `DimCity`, `DimDate` and `FactStationSnapshot` CSVs. Relate DimStation[StationNumber] to FactStationSnapshot[StationNumber], DimCity[CityKey] to FactStationSnapshot[CityKey], and DimDate[DateKey] to FactStationSnapshot[DateKey]. Use one-to-many, single-direction filters from dimensions to fact. Confirm station number uniqueness first; this dataset has repeated station numbers across records, so if DimStation has duplicates, use a composite key such as ContractName + StationNumber.
7. Save the Power BI report as `Bike_Sharing_Analysis.pbix`. A `.pbix` must be created and saved in Power BI Desktop; this package does not pretend that a PBIX was generated by a non-Power-BI environment.

## Suggested report narrative
Focus on availability and station data quality. Do not infer bike usage from a single snapshot; available bikes are a point-in-time inventory, not trips or demand.
